# Sorting and filtering records

## Learning goals
Preserve whole records during a sort and distinguish reordering from selecting records for display.

## Understand the table
In a rectangular data table, each row represents a record and each column a field. A fictional attendance table might have an identifier, group and attendance count on each row. Those entries describe one record and must stay together. Use one clear header row and inspect the selected range before applying a sort.

## Sorting changes order
Sorting arranges records in ascending or descending order by one or more fields. To order attendance counts from highest to lowest, sort the complete table by the count field in descending order. Sorting only that column separately from its identifiers can break the relationship between them. For a two-level sort, a primary field controls the broad groups and a secondary field orders records within ties. For example, sort by group first and then by attendance count within each group.

## Filtering changes which rows are visible
A filter displays records meeting a criterion. It does not need to rearrange them or delete excluded records. A numeric filter >=40 includes values equal to 40; >40 does not. Clearing a filter restores the display of rows that the filter hid. Check whether a filter is active before deciding that records have disappeared.
Filters on multiple columns narrow a selection using the specified conditions. State the desired rule in words first: “Group A records with a count of at least 40.” Then apply the group and numeric criteria and inspect a few boundary examples.

## Try it
Make four fictional records with counts 35, 40, 55 and 40. Filter for >=40 and predict three visible records. Clear the filter, sort the complete table in descending count order, and verify that every identifier still belongs to the correct count.
