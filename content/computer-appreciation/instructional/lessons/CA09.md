## Keep a record intact
Create this fictional table and save a practice copy before sorting:

| ID | Group | Count |
|---|---|---:|
| 0017 | A | 35 |
| 0021 | B | 40 |
| 0030 | A | 55 |
| 0044 | B | 40 |

Select the complete rectangular table, indicate that it has headings where your version asks, and sort by Count descending. The record with count 55 should remain paired with ID 0030 and Group A. A tie between the two 40s does not supply a unique secondary order unless another sort field is specified.
Now choose Group as the primary field and Count descending as the secondary field. The group field creates the broad groups; count determines order within each group. Sorting only the count cells breaks the relationship to IDs even if the count column is correctly ordered.

## Filter, inspect boundaries, then restore
Enable a filter for the table and apply Count >=40. Predict three visible records: 0021, 0030 and 0044. Next also require Group A; the intended intersection contains only 0030. Multiple field criteria here narrow the selection to rows satisfying both requirements.
Clear the filters and check that all four records are visible again. A filtered-out row has not been deleted, and changing the number of copies or a display format cannot restore a hidden row. Inspect active filter controls before concluding that records have vanished.

## An error investigation
After a careless single-column sort, ID 0017 is shown beside 55. Merely filtering for 55 will display that damaged association; it will not reconstruct the original record. Undo the unintended sort while possible and compare the full table with the saved practice copy. Repeat only after confirming that all fields in each record move together.
The operator >= includes equality, whereas > excludes it. This is the reason the two records at 40 remain visible in the first filter. It is **not** evidence that 40 is an official pass mark; institutional grading policy remains unresolved.
Self-check: explain why sorting and filtering can both change what you see while acting on different aspects of the table: order versus visibility.
