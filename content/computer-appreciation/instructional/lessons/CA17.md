## Consolidation exercise: check labels before totals
Prepare three small fictional monthly source tables with matching categories. For a single shared category, use totals 12, 15 and 23. The expected SUM is 50. Name the destination separately: it is where the combined result should appear, not one of the three contributing source ranges.
Following the lecturer's consolidation workflow, choose the destination, inspect the function, add each intended source reference and inspect the category/position assumptions before accepting the result. The feature can combine ranges, but it cannot infer that two similarly positioned rows really mean the same category.

| Role | Example | Error to avoid |
|---|---|---|
| Sources | Three monthly tables | Omitting or double-counting a month |
| Function | SUM | Choosing a count when a total is intended |
| Destination | Master summary | Overwriting input records |
| Category correspondence | Same item in each source | Combining unrelated items by position |

## Fixed output versus linked output
First reason about a fixed snapshot of 50. If a source later changes from 12 to 20, the stored snapshot does not thereby become 58. It represents the earlier state. For linked results, the source's link option can allow subsequent source changes to update the summary; inspect the links and result rather than assuming that every summary is live.
Use a fixed copy deliberately when an exercise asks for a stable archived state, and a correctly linked summary when a changing working model is intended. Those choices affect the relationship to inputs, not whether the source data were academically or financially approved.

## Investigate a result of 38
For 12, 15 and 23, a total of 38 corresponds to 15+23 and suggests that the 12 source may have been omitted. That is a hypothesis to inspect, not proof: inspect all source references and the function before deciding on the cause. A total of 50 can also be misleading if the wrong categories happen to add to the same number.
