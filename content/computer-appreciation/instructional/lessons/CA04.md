## Build, predict and inspect a function
Create B2:B4 containing 4, 6 and 10. In a separate cell enter =SUM(B2:B4). Trace the range first: there are three inputs, and their total is 20. Change B3 to 8; the predicted result is 22. The range means the cells currently referenced, not the original numbers permanently remembered by the formula.
When using AutoSum, inspect the highlighted endpoints before accepting its suggestion. An empty gap or adjacent subtotal can make a suggested selection unsuitable. Compare the result with a short hand calculation, especially before using the same pattern in a larger table.

## Distinguish the question being calculated
Seventeen items are packed in groups of five. Three whole groups use 15 items, leaving two. The result of =MOD(17,5) is therefore 2, whereas ordinary division produces 3.4. A remainder, quotient and total answer different questions.
Similarly, =ABS(-4.5) gives distance from zero, 4.5. It does not mean “always round upward”. For the supplied positive example, INT(3.8)=3 removes the fractional part by rounding down. These operations happen to look simple for positive values; do not substitute one function for another based on a single coinciding result.

## Date exercise: a live clock is not an event log
In one cell enter a deliberately fixed date for a fictional event. In two others enter =TODAY() and =NOW(). Inspect their formulas and apply appropriate date/time displays. The fixed input records the chosen event date; the functions request current values when recalculation occurs. A date-only display can hide a time portion in a date/time value, so a displayed date alone cannot prove which function was used.
DATE accepts year, month, day, for example =DATE(2026,10,19). The lesson's argument order is separate from local display conventions such as day/month/year. Avoid deciding an argument's meaning from how the formatted answer is printed.
